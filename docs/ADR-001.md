# ADR 001 · Management UI stack

Status: selected for V2. All four browser prototypes completed on Ubuntu 24.04.

The console has two documents, a small number of forms, a detail inspector and tables rendered from a bounded API. The selected candidate uses strict TypeScript, standard HTML controls and shared Graphite CSS. Its production JavaScript has zero package imports. TypeScript and Playwright are pinned build and test dependencies. A production installer carries the compiled assets inside the Admin executable.

| Candidate | Published reference | License | Integration and accessibility |
|---|---|---|---|
| shadcn/ui | CLI 4.23.1, registry supports Base UI and Radix | MIT | Local component source plus React, headless primitives and Tailwind. Good fit if several React tools share copy-owned components. [Official documentation](https://ui.shadcn.com/docs/official) |
| Base UI | 1.9.0 | MIT | React headless primitives; focus, keyboard and interaction support with local styling. [Releases](https://base-ui.com/react/overview/releases) |
| Radix Primitives | Individually released packages | MIT | React headless primitives with dialog and tooltip keyboard/focus APIs. [Releases](https://www.radix-ui.com/primitives/docs/overview/releases) |
| Mantine | 9.8.2 | MIT | React component library with rich patterns, theme tokens and required component CSS. [Releases](https://mantine.dev/changelog/all-releases/) |
| Ant Design | 6.7.2 | MIT | React table/forms and theming; suite behavior and CSS come with a larger integration surface. [Changelog](https://ant.design/changelog/) |
| daisyUI | 5.8.3 | MIT | Tailwind classes, CSS themes and HTML semantics. Native or application-owned behavior for focus, dialogs and interactive table options. [Changelog](https://daisyui.com/docs/changelog/) |
| Headless UI | React 2.2.10 | MIT | React/Vue headless behavior with custom styling. [Releases](https://github.com/tailwindlabs/headlessui/releases) |

For the shipped candidate, the Playwright fixture exercises a high-density connections table, native modal focus, keyboard actions, responsive widths and the local-asset constraint. The dev workstation has locked compiler and browser packages available locally. The standalone `tests/ui-prototypes.mjs` builds and measures the same form, 20-row table and keyboard dialog with native HTML/TypeScript, shadcn/Base UI, TypeScript/daisyUI and React/Mantine. It records the installed lockfiles, raw/gzip output size, isolated Chromium first-render samples and keyboard behavior. Read `ui-prototypes/comparison.json` from the matching commit's workflow artifacts for measured values.

### Measured comparison

Same 20-row table, one configuration input and a keyboard-operable dialog, built in isolated npm projects and rendered by Chromium. The package counts include development dependencies, the Vite toolchain and platform lockfile entries. Gzip sizes sum the three shipped prototype assets. Timing is the median of five local cold page renders.

| Prototype | Gzip bytes | Median visible table | Locked package entries |
|---|---:|---:|---:|
| Native HTML + TypeScript | 1,733 | 33.1 ms | 64 |
| TypeScript + daisyUI | 6,904 | 33.2 ms | 104 |
| React + shadcn/Base UI | 99,540 | 62.7 ms | 119 |
| React + Mantine | 134,618 | 72.3 ms | 87 |

All four rendered the table and opened and dismissed the labeled dialog by keyboard. The selected stack handles the current controls with native semantics and application-owned design tokens. These fixture timings compare the implementations on one runner. The full console ships without Vite or any npm runtime dependencies.
